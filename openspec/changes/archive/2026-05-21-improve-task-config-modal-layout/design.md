## Context

任务管理页面的创建/编辑任务弹窗位于 `frontend/app/pages/task-management/[id].vue`。当前弹窗容器为 `max-w-lg`，表单所有字段按单列堆叠；新增过滤规则和 STRM URL 选项后，表单高度在常见桌面视口中超过屏幕，且弹窗没有为创建/编辑表单设置最大高度和内部滚动区域。

同一页面的运行记录和运行日志弹窗已经使用 `max-h-[85vh] overflow-hidden flex flex-col` 这类结构控制视口内显示。任务配置弹窗应采用相同方向的布局约束，同时把字段组织为响应式两列。

## Goals / Non-Goals

**Goals:**

- 创建/编辑任务弹窗在桌面视口中使用更宽容器，并将表单字段分为两列展示。
- 表单内容超出视口时在弹窗内部滚动，用户可以访问全部配置项。
- 弹窗标题区和底部操作区在弹窗结构中保持独立，不被长表单内容挤出视口。
- 窄屏或移动端保持单列布局。
- 保持现有字段绑定、提交逻辑和接口请求不变。

**Non-Goals:**

- 不新增、删除或重命名任务配置字段。
- 不调整任务配置保存、校验、默认值或后端接口。
- 不引入步骤式表单、折叠面板、分页、搜索或字段显隐逻辑。
- 不新增 JavaScript 状态来控制布局。

## Decisions

1. 弹窗容器使用更宽的响应式最大宽度，并限制最大高度。
   - Rationale: 现有 `max-w-lg` 过窄，不适合两列字段；最大高度可以保证弹窗始终落在视口内。
   - Alternative considered: 继续保持窄弹窗只增加滚动。该方案能访问字段，但无法解决配置项密集导致的纵向浏览成本。

2. 表单主体使用 CSS Grid 响应式两列。
   - Rationale: 任务配置字段主要是独立输入项和选项组，用 grid 可以直接表达桌面两列、窄屏单列的布局。
   - Alternative considered: 使用 flex 手动分左右栏。该方案会让字段分组和响应式跨度更难维护。

3. 长内容放入独立滚动区域，底部操作按钮放在滚动区域之外。
   - Rationale: 用户保存或取消任务时，不应因为表单过长找不到操作按钮。
   - Alternative considered: 让整个弹窗随页面滚动。该方案会让遮罩层内交互不稳定，也不符合页面内其他大弹窗的结构。

4. 字段分组按语义设置列跨度。
   - Rationale: 任务名称、任务路径、定时任务、重命名正则等可以两列排列；过滤规则和 STRM URL 选项等成组配置可以按内容需要跨列或内部再分列。
   - Alternative considered: 所有字段机械平均分到两列。该方案会让说明文字和分组控件阅读割裂。

## Risks / Trade-offs

- [Risk] 两列布局在中等宽度屏幕上可能压缩较长占位文本。→ Mitigation: 仅在足够宽的断点启用两列，输入框继续使用现有宽度规则。
- [Risk] 滚动区域嵌套后底部按钮与表单间距变化。→ Mitigation: 使用明确的 header、scroll body、footer 三段式结构，并保持现有按钮样式。
- [Risk] 调整字段分组跨度可能影响视觉顺序。→ Mitigation: 保持 DOM 字段顺序与当前表单一致，只通过响应式布局改变横向排列。
